01 · What is Claude Code?

Anthropic's official CLI for AI-assisted software development — an intelligent pair programmer that reads, writes, and executes code.

What it CAN do

  • Read and understand your entire codebase
  • Write, edit, and refactor code across files
  • Run shell commands (git, npm, tests)
  • Search the web for documentation
  • Create and review pull requests

What it WON'T do

  • Replace human judgment on design
  • Understand your domain magically
  • Execute destructive commands without asking
  • Remember context between sessions

03 · The Work-Loop

Four phases that take you from idea to merged code. Each phase has a dedicated skill.

flowchart LR
    P["/planning"] --> E["/execution"]
    E --> R["/reviewing"]
    R --> I["/integration"]
    R -->|NEEDS_FIXES| E
    I --> Done["✅ Merged"]
Key insight: Each phase produces artifacts that the next phase consumes. The loop is idempotent — you can restart from any point.

04 · /planning Phase

Analyze the codebase, understand requirements, write a task list so precise that execution never needs to make a design decision.

sequenceDiagram
    participant Dev
    participant Claude
    participant Files
    Dev->>Claude: /planning "add dark mode"
    Claude->>Files: Read CLAUDE.md, components
    Claude->>Files: Write docs/plans/feature-plan.md
    Claude->>Dev: Task list with file paths
Output: plan.md with concrete tasks, file paths, verify commands
Rule: No code written! Planning only.

05 · /execution Phase

Implement tasks one at a time from the plan. Test-Driven Development by default.

sequenceDiagram
    participant Claude
    participant Files
    participant Tests
    loop For each task
        Claude->>Files: Write failing test
        Tests->>Claude: ❌ Fails (expected)
        Claude->>Files: Implement feature
        Tests->>Claude: ✅ Passes
        Claude->>Files: Update progress.md
    end
TDD cycle: Red (failing test) → Green (make it pass) → Refactor

06 · /reviewing Phase

Self-review against acceptance criteria. Output is APPROVED or NEEDS_FIXES.

Review Checklist

  • All acceptance criteria met?
  • Tests exist and pass?
  • No debug code?
  • Follows conventions?
  • No security issues?

Outcomes

APPROVED → /integration
NEEDS_FIXES → /execution

07 · /integration Phase

Create PR, handle CI, get it merged.

git add -p
git commit -m "feat(timer): add start/stop functionality"
git push -u origin feature/add-timer
gh pr create --base develop
Done: Feature merged to develop, branch cleaned up.

08 · /grill-me — Clarify Before You Build

Socratic questioning until your concept is crystal clear. Run BEFORE /planning.

Questions You'll Face

  • Problem: What are you solving?
  • Users: Who will use this?
  • Differentiator: Why not existing?
  • Core: ONE thing it must do?
  • Non-goals: NOT in v1?

Output

## Concept: TimeTracker
**Problem:** Freelancers lose hours
**Core:** One-click timer
**Non-goals:** Invoicing (v2)
Don't defend — refine. Each pushback finds holes before you code.

10 · /tdd — Test-Driven Development

Write the test first. Make it fail. Then make it pass.

flowchart LR
    R["🔴 RED
Failing test"] --> G["🟢 GREEN
Make it pass"]
    G --> RF["🔵 REFACTOR
Clean up"]
    RF --> R
Never skip RED: A test that never failed might pass by accident.
Minimal GREEN: Simplest code that passes. Refactor after.

11 · Git Workflow

Feature branches, PRs required, never commit to main.

git checkout -b feature/add-timer develop
claude
/planning "implement timer component"
/execution
/reviewing
git add -p && git commit -m "feat(timer): add timer"
git push -u origin feature/add-timer
gh pr create --base develop
Never push to main directly. Main is production.

22 · The Non-Determinism Problem

Industry data: AI code has 1.7× more defects · Solution: Harness Engineering

The Reality

Claude is an image generator for code, not a compiler. Output varies between runs.

What to Expect

  • Different output each run
  • Hallucinations happen
  • Instructions sometimes ignored
  • Model versions differ

The Solution: Guardrails

LayerToolCatches
Pre-commitBiome, TypeScript, hooksSyntax, formatting, types
CITests, E2E, lintingLogic errors, regressions
ReviewHuman code reviewArchitecture, security, edge cases
The Rule: More Claude power = tighter leash
Harden Over Time: Every Claude mistake → new automated check
