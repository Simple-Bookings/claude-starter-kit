# /github-issues — Issue Creation

Create well-structured, actionable GitHub issues.

## Feature request template

```markdown
## Description
[Clear, concise description of what's needed]

## Acceptance Criteria
- [ ] AC1: [Specific, testable criterion]
- [ ] AC2: [Another criterion]
- [ ] AC3: [And another]

## Technical Notes
[Implementation hints, relevant files, dependencies]

## Definition of Done
- [ ] Code implemented and tested
- [ ] Tests pass locally
- [ ] PR reviewed and approved
- [ ] Merged to develop
```

## Bug report template

```markdown
## Bug Description
[What's broken]

## Steps to Reproduce
1. [First step]
2. [Second step]
3. [See error]

## Expected Behavior
[What should happen]

## Actual Behavior
[What actually happens]

## Environment
- OS: [e.g., macOS 14.0]
- Browser: [e.g., Chrome 120]
- Version: [e.g., v1.2.3]
```

## Labels

| Label | Meaning |
|-------|---------|
| `bug` | Something isn't working |
| `feature` | New functionality |
| `docs` | Documentation |
| `P0-critical` | Must fix immediately |
| `P1-high` | High priority |
| `good-first-issue` | Good for newcomers |

## Rules

- One issue = one thing
- Write testable acceptance criteria
- Link related issues
- Add appropriate labels
